# Governance

Paper Amigo currently uses maintainer-led governance. Maintainers set release
scope, review changes, manage repository access, and enforce project policies.

Project decisions should happen in issues or pull requests when they can be
public. A proposal should state the problem, constraints, alternatives, and
migration cost. Maintainers decide after giving affected contributors a
reasonable chance to comment.

Maintainer status is based on sustained, trusted contributions and sound review
judgment. Existing maintainers approve new maintainers. Access can be reduced or
removed after inactivity, security concerns, or a code of conduct violation.

Security reports, conduct reports, and personal data stay private. The public
record should contain only the decision or technical change needed by project
users.
